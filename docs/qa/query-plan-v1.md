# QueryPlan 复合问答框架 v1

## 目标

`QueryPlan` 位于确定性目录规则、图谱检索、DeepSeek 推理和回答降级之前。它解决的不是某一句话的关键词匹配，而是让所有后续模块共享同一份问题理解结果。

## 执行顺序

1. 解析当前问题和最近三轮用户约束。
2. 生成结构化计划：意图、关系类型、包含条件、排除条件、软偏好、数量要求和安全边界。
3. 安全边界先于模型执行。宠物安全没有官方认证时直接拒绝具体商品推荐。
4. 纯目录问题可走确定性完整列表；关系、价格、规格、推荐和多轮问题不能被目录规则抢答。
5. 服务器按计划预先执行图谱或商品检索，再把结果交给 DeepSeek 推理和表达。
6. 模型不可用时，使用同一批检索事实生成保守答案，不返回空白，也不放宽硬条件。

## 当前计划字段

- `intent`：catalog、fact、relation、recommendation、comparison、gifting、safety。
- `relationIntent`：layering、accessory、refill_compatibility、series_membership、pairing。
- `constraints`：商品大类、品型、系列、规格、补充装标签、最高价格，以及系列和品型排除项。
- `inheritedConstraintKeys`：明确记录哪些条件来自上一轮。
- `softPreferences`：木质、清冷、柔和、卧室等只能用于排序、需要文案证据的偏好。
- `recommendationLimit`：识别“三款”等明确数量要求。
- `requiresEvidence`：关系、比较、核对和依据追问必须取商品详情或已审核关系。
- `safety`：当前先覆盖宠物安全无依据时的硬拦截。

## 已验证行为

- “杜桑系列有哪些产品”稳定完整返回 9 款商品。
- “杜桑淡香水有哪些容量”只命中该商品并返回 50ML、100ML。
- “除了香水的杜桑同系列产品”排除淡香水和淡香精。
- “不要玫瑰味”转成真实的系列排除条件。
- “香膏有没有补充装”只检索真实补充装标签。
- 影中之水洁肤露叠香沿已审核 `LAYER_WITH` 关系检索。
- 宽泛蜡烛配件查询扫描全部匹配蜡烛的已审核 `ACCESSORY_FOR` 关系。
- “家居产品有哪些”后追问送长辈，会继承家居香氛和艺术家居范围。
- “500 元以内蜡烛”后追问卧室，会同时保留价格和蜡烛品型。
- 宠物安全问题不返回商品卡片，不把气味柔和推断为安全。
