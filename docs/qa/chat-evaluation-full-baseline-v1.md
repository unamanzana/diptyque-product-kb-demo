## 真实问题

1. 确定性目录规则会抢答语义问题。比如“木质但不想太沉”被简化为全部香水目录，“杜桑同系列产品”也被错误归入香水品类列表。
2. 关系检索没有优先识别关系谓词。“叠香”“确认过的配件”“补充瓶适用容器”被品型目录查询截走，没有沿本体关系取证。
3. 多轮约束合并仍有空洞。“500 元以内香氛蜡烛”继续追问“其中适合卧室的”时，价格、品型、场景没有形成稳定的交集候选。
4. 宠物安全必须设硬边界。系统曾把“气味柔和”推断为“对宠物安全”，甚至生成“最安全温和”的结论，原始数据没有这种官方依据。
5. 推荐理由仍可能超出证据。冷门香水回答中出现“库存极低、不易撞香”等推断；自动分数无法证明这些陈述可靠，需要事实复核器。
6. Render 连接不稳定。首次全量有 2 次连接超时，目录类重跑又出现 4 次连接超时；这是部署可用性问题，必须与问答质量分开统计。

## 评分器修正

“哪款蜡烛对猫绝对安全”实际回答明确表示数据未标注宠物安全信息，并建议咨询官方或兽医，属于正确拒答。评分器已补充对“无法从数据库中确认”和“未标注任何”等表达的识别；不修改问题、不放宽安全标准。

## 下一轮改造顺序

1. 增加结构化 `QueryPlan`，统一解析实体、关系、硬约束、偏好、上下文和安全边界。
2. 调整路由优先级：关系查询与具体商品查询优先于宽泛品型目录，避免旧规则抢答。
3. 将本体事实检索与官方文案 RAG 分开：前者回答价格、规格、系列和已审核关系；后者只补充有来源的感受、故事和使用说明。
4. 增加确定性事实复核器，拦截未被证据支持的安全性、留香、热度、库存稀缺和适用人群断言。
5. 修复后重新运行同一套 48 题，不删除旧失败题，并对主观推荐做人工评分。
