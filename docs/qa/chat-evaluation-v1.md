# Diptyque 问答评测 v1

## 目标

这套评测用于区分问答失败发生在哪一层，而不是针对单个问法继续增加特例。评测集固定包含 48 个案例，每类 6 个：

1. `catalog_fact`：商品、价格、规格等精确事实。
2. `ontology_relation`：系列、叠香、补充装、配件和兼容关系。
3. `fuzzy_preference`：清冷、自然、不甜、雨后花园等模糊偏好。
4. `multi_constraint`：预算、类别、香调、场景和排除条件组合。
5. `comparison`：商品或系列之间的事实比较。
6. `gifting`：送礼对象、预算、品类和组合建议。
7. `multi_turn`：上下文继承、指代和条件收窄。
8. `challenge_safety`：依据追问、事实纠错和应当拒绝推断的安全问题。

测试数据位于 `evals/diptyque-chat-eval-v1.json`。

## 两类评分

自动评分负责可确定判断：

- 回答是否为空、是否应当拒绝推断；
- 商品名称是否能回到当前商品快照；
- 价格、商品大类和品型是否满足条件；
- 是否错误返回补充装；
- 完整列表是否覆盖必须商品；
- 回答是否包含必要事实或出现禁止说法。

人工评分负责不能假装有唯一标准答案的部分：

- 模糊气味是否理解合理；
- 推荐理由是否真正由官方文案支持；
- 商品之间的差异是否清楚；
- 推荐是否有多样性；
- 是否使用性别、热度或留香时长等无依据判断。

## 命令

只校验评测集结构和商品引用，不调用模型：

```powershell
npm run audit:chat-evals
```

调用本地问答接口运行全部案例：

```powershell
npm run eval:chat
```

只跑某一类或少量案例：

```powershell
npm run eval:chat -- --category catalog_fact
npm run eval:chat -- --category multi_turn --limit 3
```

评测线上 Render：

```powershell
npm run eval:chat -- --base-url https://diptyque-product-kb.onrender.com/api/chat
```

加上 `--strict` 后，平均分低于 90 或出现请求失败时返回失败状态。报告写入忽略提交的 `temp/chat-evals/latest.json` 和 `temp/chat-evals/latest.md`。

## 迭代规则

- 先保存当前版本基线，再改检索或提示词。
- 每个失败归入理解、检索、排序、证据、生成、上下文或界面同步。
- 修复共性根因，不为评测题增加逐句硬编码。
- 新发现的真实问题加入回归集，旧问题不删除。
- 主观案例需要保留人工审核，不用模型自己给自己打满分。
- 安全、价格、规格、补充装和商品关系发生幻觉时，即使平均分较高也不能发布。

## 下一阶段复合框架

基线完成后，按失败分布逐步加入：

1. 结构化 `QueryPlan`，稳定解析当前问题和多轮约束。
2. 本体检索，负责商品、价格、规格和已审核关系。
3. 官方文案混合 RAG，负责模糊感受、故事、场景和使用说明。
4. 候选重排，综合硬条件、语义相关性和证据质量。
5. 确定性事实复核，保证回答、商品卡片和图谱节点一致。
